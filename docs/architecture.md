# Структура и расписание

## Что внутри

```text
univerapp/
├── index.html                # Главная страница
├── assets/                   # Ресурсы интерфейса
│   ├── css/                  # Оформление, шрифты и анимации
│   ├── js/                   # Логика интерфейса и service worker
│   ├── fonts/                # Manrope и лицензия
│   └── media/                # Видео фона
├── api/                      # Обработчики Vercel
│   └── _lib/                 # Platonus, чат и Telegram
├── supabase/migrations/      # SQL-миграции по порядку: 001 → 002 → 003
├── tests/
│   ├── ui/                   # Интерфейс и браузерная логика
│   ├── api/                  # Серверные запросы и уведомления
│   └── database/             # SQL и контроль доступа
├── scripts/                  # Проверка структуры и ресурсов
├── docs/                     # Документация
├── package.json              # Команды и зависимости
├── package-lock.json         # Зафиксированные версии зависимостей
├── vercel.json               # Настройки размещения
└── .env.example              # Пример переменных без секретов
```

- `index.html` — разметка экранов и подключение ресурсов. Стили и JavaScript
  вынесены в `assets/`, где браузер может кэшировать их отдельно от страницы.
- `assets/js/app.js` — вход, расписание с переключением недель, оценки,
  УМКД (с открытием PDF прямо внутри приложения), заготовка под экзамены.
- `api/login.js` — логинится в Platonus от имени студента, отдаёт временный `session`
  (без пароля).
- `api/gpa.js` — GPA + studentID/имя студента (используется сразу после входа).
- `api/schedule.js` — расписание из Platonus. Без явных параметров сам разбирается,
  какая неделя сейчас настоящая текущая (см. ниже про особенности недель);
  с явными `year`/`term`/`week` отдаёт расписание конкретной недели — так работает
  листание стрелками в приложении.
- `api/grades.js` — оценки/успеваемость по предметам (журнал): каждый предмет —
  проценты (`centerMark`, `color`) плюс список показателей (`exams`: Ср.тек. 1/2,
  РК 1/2, Рейтинг, Экз./Курс.р.).
- `api/umkd.js` — список дисциплин УМКД на семестр (название, преподаватель,
  готов ли файл — `umkdFileGenerated`/`fileId`).
- `api/umkd-file.js` — отдаёт сам PDF конкретного документа УМКД (Силлабус/Конспект
  лекций/Планы занятий/Материалы контроля), проксируя `downloadPdfUmkd` у Platonus.
  В приложении PDF рисуется через PDF.js. Запрос просмотра использует заголовок `x-session`; ссылка для нативного скачивания Telegram поддерживает `?session=`.
- `api/_lib/platonus.js` — общие хелперы (сборка заголовков, кодирование/декодирование
  сессии).


## Особенности номера недели (важно, если будешь трогать `api/schedule.js`)

Platonus странно ведёт себя с недельной нумерацией без явных параметров:
- Если не передавать `year`/`term`/`week` вообще, поле `selectedWeek` в ответе иногда
  возвращает "заглушку" (например `1`), которая не совпадает с реальной текущей неделей.
  Надёжнее в этом случае поля `defaultSelectedWeek`/`activeWeekNumber` — они не зависят
  от того, что было запрошено, и всегда указывают на настоящую текущую учебную неделю.
- Если же `year`/`term`/`week` переданы явно (навигация стрелками в приложении),
  `selectedWeek` в ответе корректно отражает именно то, что было запрошено — тогда
  доверяем именно ему.
- Приложение сохраняет это как флаг `hadExplicitOverride` при разборе ответа
  (`buildScheduleEntryFromPlatonus` в `assets/js/app.js`) — если будешь менять логику
  выбора недели, важно сохранить это разделение.
- Недели у Platonus 1-based (первая неделя семестра — «1», не «0») и их максимум
  обычно 15 за семестр — это захардкожено в `MAX_TERM_WEEKS`.
- Расписание каждой открытой недели кэшируется отдельно (в памяти и в Telegram
  CloudStorage, ключи вида `platonus_week_<year>-<term>-<week>`), поэтому повторное
  открытие уже просмотренной недели показывается мгновенно, а свежие данные
  подтягиваются в фоне.
