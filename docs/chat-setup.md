# Подключение чата: Supabase + Vercel

Код уже в проекте. Чтобы сообщения сохранялись и приходили на другие устройства,
нужно создать базу и подключить её к опубликованному приложению. Терминал не нужен.

## 1. Создай проект Supabase

1. Открой [панель Supabase](https://supabase.com/dashboard) и войди в свой аккаунт
   или зарегистрируйся.
2. Нажми **New project**, выбери свою организацию и назови проект `univerapp-chat`.
3. Задай пароль базы и сохрани его у себя. В чат его отправлять не нужно.
4. Выбери регион ближе к серверу приложения. В `vercel.json` указан Frankfurt
   (`fra1`), поэтому для базы также подойдёт Frankfurt, если доступен.
5. Дождись готовности проекта. Перед созданием проверь выбранный тариф.

## 2. Создай таблицы

1. В проекте Supabase открой **SQL Editor → New query**.
2. Открой файл [001_chat.sql](../supabase/migrations/001_chat.sql) из этого
   репозитория и скопируй весь текст в редактор.
3. Нажми **Run**. Запрос создаёт таблицы, индексы и функции, включает RLS и закрывает
   прямой доступ публичным ролям. Повторный запуск этого файла допустим.

## 3. Подключи Vercel

1. В Supabase найди **Project URL** и серверный **Secret key** в настройках API
   проекта / **Connect**. Подойдёт ключ `sb_secret_…`; для старых проектов также
   поддерживается ключ **service_role**. Ключ `anon` или `publishable` не подходит.
2. В [Vercel](https://vercel.com/dashboard) открой проект приложения →
   **Settings → Environment Variables**.
3. Добавь две переменные для **Production** (и **Preview**, если хочешь проверять
   предварительные сборки):

   | Имя | Значение |
   | --- | --- |
   | `SUPABASE_URL` | Project URL, например `https://your-project.supabase.co` |
   | `SUPABASE_SERVICE_ROLE_KEY` | Серверный Secret key или service_role |

4. Эти значения вводятся только в настройки Vercel. Не вставляй их в HTML,
   JavaScript браузера, GitHub или сообщения. `.env.example` содержит только образец.
5. В GitHub Desktop выбери изменения, введи описание коммита, нажми
   **Commit**, затем **Push origin**. Если Vercel подключён к репозиторию,
   он запустит новую сборку. Если код уже отправлен, открой **Deployments**
   в Vercel и нажми **Redeploy** последнего развёртывания: новые переменные
   применяются после развёртывания.

## 4. Проверь на двух аккаунтах

1. Войди в приложение первым аккаунтом Platonus и открой «Чаты».
2. Второй пользователь должен войти своим аккаунтом и тоже открыть «Чаты».
   Только после этого его имя появится в поиске.
3. Найди пользователя по двум или более буквам имени и отправь сообщение.
4. На втором устройстве открой переписку: сообщение должно появиться после
   очередного обновления (обычно через 2,5 секунды в открытой переписке).
5. Перезагрузи приложение и проверь историю. Выйди из аккаунта и войди другим:
   переписка предыдущего пользователя должна исчезнуть.

## Если не подключается

- «Чат пока не подключён»: проверь обе переменные, запуск SQL и новое
  развёртывание Vercel.
- Пользователь не найден: он ещё не открывал вкладку «Чаты» либо имя отличается
  от введённого. Поиск использует имя из Platonus.
- Platonus недоступен: первичное подтверждение личности требует связи с Platonus.
  Повтори позже; для уже открытой сессии сообщения используют отдельную базу.
- Ошибка сети: проверь интернет и нажми «Повторить». Не публикуй секретные ключи
  при обращении за помощью.

История чата не записывается в localStorage и не попадает в кэш service worker.
Доступ проверяется сервером для каждого запроса. При выходе сессия чата отзывается;
если сеть недоступна, серверная сессия истекает через 8 часов. Сообщения остаются
в базе, чтобы история была доступна после следующего входа.

Справка: [ключи Supabase](https://supabase.com/docs/guides/api/api-keys),
[Row Level Security](https://supabase.com/docs/guides/database/postgres/row-level-security).
