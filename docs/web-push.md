# Push-уведомления unLink.

## Включение на рабочем сайте

1. После миграций 001–008 выполни [010_web_push.sql](../supabase/migrations/010_web_push.sql) в Supabase SQL Editor. 009 нужна для новостей версий и не является зависимостью push. Миграция 010 повторно применима и сохраняет переписки.
2. Опубликуй обновлённую версию и нажми «Обновить приложение» на устройстве.
3. Открой **Профиль → Уведомления → Push на этом устройстве** и разреши уведомления в системном диалоге. Запрос разрешения никогда не вызывается автоматически при запуске.
4. Нажми **Отправить тестовое уведомление** (не чаще раза в минуту). Затем проверь сообщение со второго аккаунта при закрытом unLink.. Принятие push провайдером ещё не подтверждает его показ устройством.

На iPhone требуется iOS 16.4+ и приложение, добавленное на экран «Домой». Обычная вкладка Safari и встроенная страница Telegram не заменяют установленное веб-приложение. На Android используется поддерживающий Web Push браузер, например Chrome; приложение из Google Play не требуется. Режим фокусирования, разрешения ОС, сеть, энергосбережение и принудительная остановка браузера могут задержать или заблокировать доставку.

## Telegram без дублей

Включение push атомарно отключает уведомления о сообщениях в Telegram для аккаунта. Новости версий из [отдельной рассылки](release-announcements.md) остаются включены. Переключатель **Дублировать в Telegram** разрешает оба способа только по явному выбору пользователя. При выключенном push можно оставить Telegram единственным способом. Настройка Telegram общая для аккаунта, а push включается отдельно на каждом устройстве (до 10 устройств).

## Сервер и безопасность

Дополнительные переменные VAPID не нужны. Первая авторизованная загрузка настроек создаёт пару VAPID на сервере. В браузер передаётся только публичный ключ; приватный ключ хранится в `chat_push_keyring` с AES-256-GCM, используя серверный `UNILINK_SESSION_KEY`. Не меняй этот секрет без переноса зашифрованных ключей: его потеря потребует новой пары VAPID и повторной подписки устройств. Таблицы ключей, предпочтений, подписок и очереди закрыты RLS/правами от публичных ролей. Токены и endpoint подписок не выводятся в логи.

Подписка привязана к подтверждённому сервером аккаунту и устройству. Сервер проверяет endpoint push-провайдера и ключи; произвольные URL, локальные IP и нестандартные порты не разрешены. Истёкшие endpoint (404/410) удаляются. Привязка учётной записи в IndexedDB дополнительно проверяется service worker перед показом и открытием уведомления: выход или смена аккаунта не должны раскрыть сообщение старого аккаунта. Выход закрывает уведомления, отзывает подписку устройства и удаляет её на сервере. Нажатие уведомления открывает только проверяемую сервером переписку на том же сайте.

Перед отправкой сервер проверяет активность именно устройства подписки через `session_hash` и `chat_presence` из миграции 005. Пока unLink. виден на этом устройстве, задание помечается `suppressed` без обращения к push-провайдеру; сообщения и счётчик непрочитанных обновляются внутри приложения. Другие устройства аккаунта продолжают получать push. При сворачивании отправляется сигнал неактивности; если ОС завершила процесс без этого сигнала, последняя отметка активности истекает в течение 45 секунд. Уже отправленный push может дойти после открытия приложения. При недоступной проверке активности сохраняется обычная доставка. Новая миграция для этого поведения не нужна, достаточно ранее применённой 005 и 010.

Полученный push не скрывается молча в service worker: Safari требует видимого уведомления и может отозвать подписку при нарушении. Поэтому отключение дублей выполняется до отправки, на сервере. [Ограничение WebKit](https://webkit.org/blog/16535/meet-declarative-web-push/).

Очередь заполняется транзакционно при записи сообщения и отправляется сервером через `waitUntil` после ответа отправителю: открытое приложение получателя не требуется. Временные ошибки повторяются сразу, затем оставшиеся задания могут подхватываться при следующих отправках/запросах отправителя. Отдельного постоянно работающего планировщика в этой версии нет. Push-провайдер может держать сообщение для офлайн-устройства до 24 часов. Подписка действует до 180 дней; отключённый браузером endpoint может прекратить работать раньше. Это доставка по возможности, а не гарантия каждой нотификации; сама переписка остаётся в базе независимо от уведомлений.

На настоящих устройствах нужно проверить: закрытие приложения, получение уведомления, переход в правильный чат, отсутствие Telegram-дубля, отказ разрешения, выход и смену аккаунта. Автотесты проверяют серверную очередь, права, ключи, переключатели и обработчики service worker с моделированием провайдера.

Справка: [WebKit о push для iPhone](https://webkit.org/blog/13878/), [web-push](https://github.com/web-push-libs/web-push).
