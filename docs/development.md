# Разработка и проверки

## Локальный запуск

Рекомендуется Node.js 24; минимальная заявленная версия — 22. Установи зависимости и проверь проект:

```sh
npm ci
npm run verify
```

Для полного приложения нужен сервер `/api`: используй официальный Vercel CLI и `vercel dev`. Создай `.env.local` по [.env.example](../.env.example); файл игнорируется Git. Обычный HTTP-сервер подходит только для макета интерфейса. Проверки работают на вымышленных данных без настоящих секретов.

## Команды

| Команда | Что проверяет |
| --- | --- |
| `npm run check` | Синтаксис JS, ресурсы HTML/CSS, Markdown-ссылки, manifest и пути worker |
| `npm test` | Все тесты |
| `npm run test:api` | API, ответы upstream, защита входа и восстановление |
| `npm run test:ui` | Навигация, кэш, состояния загрузки, гонки и viewport |
| `npm run test:database` | SQL, ограничения, доступ, лимиты и миграции |
| `npm run verify` | `check`, затем все тесты |

[GitHub Actions](../.github/workflows/checks.yml) запускает `npm ci` и `npm run verify` на push и pull request с правом только чтения репозитория. Для нового модуля добавляй его в существующий каталог по назначению; формат файлов задаётся [.editorconfig](../.editorconfig) и [.gitattributes](../.gitattributes).

## Состояния и хранение

- Учебные данные зеркалируются в localStorage с префиксом пользователя Telegram; повторное открытие сначала использует кэш, затем обновляет данные в фоне. В браузере сохраняется текущий аккаунт этого профиля браузера.
- Чтения Telegram CloudStorage объединяются и ограничены тайм-аутом 5 секунд. Данные больше 4096 символов остаются локально.
- Пароля в браузерных хранилищах нет. Основной вход — HttpOnly cookie; при запоминании используются отдельный зашифрованный пакет и ключ устройства: IndexedDB в браузере, SecureStorage и резервная браузерная копия в Telegram 9.0+. Сбои этих хранилищ не блокируют успешный вход. Подробности — в [описании сессий](security.md).
- Расписание с известным studentID не ждёт GPA. Готовые оценки и УМКД отображаются независимо от более медленных запросов. Ошибки пустого журнала не подменяют уже полученные данные.
- Незавершённые запросы проверяют поколение авторизации. После выхода ответы старого аккаунта не должны восстанавливать интерфейс, cookie или запись устройства.
- История сообщений хранится только в памяти текущего сеанса интерфейса и в Supabase; не добавляй её в localStorage или кэш worker.

## Публичная оболочка и обновления

`assets/js/sw.js` обслуживает корень благодаря `Service-Worker-Allowed: /` из `vercel.json`. Он кэширует только перечисленные публичные файлы; API и внешние ресурсы обходят кэш. HTML проверяется по сети, при отсутствии сети используется сохранённый. CSS и JS текущей версии читаются из кэша с фоновым обновлением.

При добавлении подключаемого модуля обнови `index.html`, список `SHELL_PATHS` и версию кэша. После публикации проверь кнопку **Профиль → Обновить приложение**: она обновляет публичные файлы и перезагружает страницу без очистки пользовательских данных. Новая разметка должна оставаться совместимой с предыдущей оболочкой во время обновления.

## Производительность и интерфейс

Фон рисуется Canvas 2D без видео. Разрешение ограничено 240 000 пикселями, движение — 24–30 кадрами в секунду; скрытая страница, reduced motion и экономия трафика останавливают анимацию. Manrope хранится локально с лицензией OFL. Типографика и общие отступы задаются CSS-переменными.

Время и прогресс занятий обновляются раз в 15 секунд и при возвращении в приложение. Скрытые экраны пропускают ненужные перерисовки. Новые сетевые операции должны иметь тайм-аут и обрабатывать смену аккаунта.

На реальных устройствах проверяй: запуск установленной PWA, полное закрытие и открытие, клавиатуру в переписке, видимую шапку, возврат таббара вниз, поворот экрана, Android и Telegram. Браузерные тесты не заменяют системное завершение iOS-приложения.

## Текущие ограничения

- Экзамены используют пустой `EXAMS_SCHEDULE`: источник реального расписания не подключён.
- Типы PDF УМКД заданы фиксированными `fileTypeID` 131/133/134/138; другие наборы требуют проверки ответа Platonus.
- Формат журнала, календаря и учебных полей зависит от Platonus. Изменения парсинга проверяй на обезличенных примерах, не добавляя реальные ответы с личными данными в Git.
- Инструменты переноса базы отделены в `scripts/maintenance/`; они не участвуют в сборке или работе сайта. [Инструкция](database-maintenance.md).
