# Разработка и проверки

## Локальный запуск

Рекомендуется Node.js 24; минимальная заявленная версия — 22. Установи зависимости и проверь проект:

```sh
npm ci
npm run verify
```

Для полного приложения нужен сервер `/api`: используй официальный Vercel CLI и `vercel dev`. Создай `.env.local` по [.env.example](../.env.example); файл игнорируется Git. Обычный HTTP-сервер подходит только для макета интерфейса. Проверки работают на вымышленных данных без настоящих секретов.

## Команды

| Команда | Что проверяет |
| --- | --- |
| `npm run check` | Синтаксис JS, ресурсы HTML/CSS, Markdown-ссылки, manifest и пути worker |
| `npm test` | Все тесты |
| `npm run test:api` | API, ответы upstream, защита входа и восстановление |
| `npm run test:ui` | Навигация, кэш, состояния загрузки, гонки и viewport |
| `npm run test:database` | SQL, ограничения, доступ, лимиты и миграции |
| `npm run verify` | `check`, затем все тесты |

[GitHub Actions](../.github/workflows/checks.yml) запускает `npm ci` и `npm run verify` на push и pull request с правом только чтения репозитория. Для нового модуля добавляй его в существующий каталог по назначению; формат файлов задаётся [.editorconfig](../.editorconfig) и [.gitattributes](../.gitattributes).

## Состояния и хранение

- Учебные данные зеркалируются в localStorage с префиксом пользователя Telegram; повторное открытие сначала использует кэш, затем обновляет данные в фоне. В браузере сохраняется текущий аккаунт этого профиля браузера.
- Чтения Telegram CloudStorage объединяются и ограничены тайм-аутом 5 секунд. Данные больше 4096 символов остаются локально.
- Пароля в браузерных хранилищах нет. Основной вход — HttpOnly cookie; при запоминании используются отдельный зашифрованный пакет и ключ устройства: IndexedDB в браузере, SecureStorage и резервная браузерная копия в Telegram 9.0+. Сбои этих хранилищ не блокируют успешный вход. Подробности — в [описании сессий](security.md).
- Расписание с известным studentID не ждёт GPA. Готовые оценки и УМКД отображаются независимо от более медленных запросов. Ошибки пустого журнала не подменяют уже полученные данные.
- Контрольные точки переключаются между «РК 1», «РК 2» и «Все». Границы берутся из календаря нужного учебного года и семестра. Выходные после окончания РК 1 остаются в первом периоде; РК 2 начинается со следующего буднего дня. Например, окончание календарной недели РК 1 24.10.2026 даёт РК 1 до 25.10 включительно и РК 2 с понедельника 26.10. Конечная дата РК 2 берётся из календаря. Оценки вне этих дат доступны в «Все» отдельным блоком. Если календарь недоступен или неоднозначен, показываются все оценки с пояснением и повторной загрузкой календаря. Календарь использует общий кэш учебных документов; переключение периода не запрашивает оценки заново.
- «Динамика» — четвёртая вкладка после «Все». Она показывает статичный SVG-график за весь семестр без кнопок на точках и выбора даты; вкладки РК 1, РК 2 и «Все» содержат таблицы оценок. Точки показывают простое среднее за каждую дату по всем видам занятий, шкала всегда 0–100. Общее среднее рассчитывается по всем исходным оценкам, включая нули; сравнение — между средними последней и первой дат. Итоги РК из журнала остаются отдельными показателями. Одна дата не создаёт сравнения, пустой семестр не создаёт графика. Динамика доступна и без академического календаря, переключение вкладок не запрашивает оценки заново.
- Разбор контрольных точек принимает числовые оценки и десятичные строки с точкой или запятой; явно пустые коллекции `null`, `{}` и `[]` не блокируют заполненные группы. Некорректные даты, неподдерживаемые оценки и непустые коллекции неизвестной структуры остаются ошибками. API возвращает безопасный код диагностики: `GD_FORMAT`, `GD_TIMEOUT`, `GD_PROFILE` или `GD_UPSTREAM`; интерфейс показывает пояснение и повторную загрузку без исходного ответа Platonus.
- Кириллическая «н» в контрольных точках сохраняется как `{mark:null,status:'absent',date}` и отображается в таблице как отсутствие на занятии. Она не входит в счётчики числовых оценок, среднее и динамику; настоящий балл 0 учитывается. Даты отсутствий фильтруются по РК так же, как даты оценок, а записи вне календарных периодов доступны в «Все».
- Ошибка формата контрольных точек содержит уточнение поля и типа, например `GD_FORMAT_DATE_NULL` или `GD_FORMAT_MARK_NUMBER_NEG1`. Для коротких текстовых отметок указываются Unicode-коды (чтобы различать кириллическую «Н» и латинскую `H`), для произвольных строк — только тип. Имена, учётные данные и полный ответ Platonus в диагностику не включаются. `GD_FORMAT_UI` означает ошибку чтения на клиенте и предлагает обновить оболочку; `GD_FORMAT_JSON` — невалидный JSON от Platonus.
- Незавершённые запросы проверяют поколение авторизации. После выхода ответы старого аккаунта не должны восстанавливать интерфейс, cookie или запись устройства.
- Полная история сообщений хранится в Supabase. В памяти — до 10 переписок по 200 сообщений; для быстрого восстановления вкладки в `sessionStorage` сохраняются до 5 переписок по 40 сообщений, отдельно для аккаунта и со сроком восемь часов. Выход удаляет предпросмотр. Не переноси переписки в localStorage или кэш worker.

## Публичная оболочка и обновления

`assets/js/sw.js` обслуживает корень благодаря `Service-Worker-Allowed: /` из `vercel.json`. Он кэширует только перечисленные публичные файлы; API и внешние ресурсы обходят кэш. HTML, CSS и JS читаются из кэша одной версии без фоновой перезаписи. Если файла нет, worker запрашивает его с контрольной суммой из `SHELL_INTEGRITY`, которую формирует сборщик. Файл другой публикации не пройдёт проверку. Отдельные файлы предыдущих версий не используются для заполнения текущего кэша.

При добавлении подключаемого модуля обнови `index.html` и список `SHELL_PATHS`. Сборщик автоматически формирует идентификатор версии и контрольные суммы после подстановки версии в файлы. Новый worker сначала скачивает все файлы оболочки; ошибка HTTP, сети или контрольной суммы прерывает установку до активации. После публикации проверь кнопку **Профиль → Обновить приложение**: она обновляет публичные файлы и перезагружает страницу без очистки пользовательских данных. Новая разметка должна оставаться совместимой с предыдущей оболочкой во время обновления.

## Производительность и интерфейс

Фон рисуется Canvas 2D без видео. Разрешение ограничено 240 000 пикселями, движение — 24–30 кадрами в секунду; скрытая страница, открытая экранная клавиатура, reduced motion и экономия трафика останавливают анимацию. Manrope хранится локально с лицензией OFL. Типографика и общие отступы задаются CSS-переменными.

Время и прогресс занятий обновляются раз в 15 секунд и при возвращении в приложение. Скрытые экраны пропускают ненужные перерисовки. Новые сетевые операции должны иметь тайм-аут и обрабатывать смену аккаунта.

На реальных устройствах проверяй: запуск установленной PWA, полное закрытие и открытие, клавиатуру в переписке, видимую шапку, возврат таббара вниз, поворот экрана, Android и Telegram. Браузерные тесты не заменяют системное завершение iOS-приложения.

## Текущие ограничения

- Расписание экзаменов загружается через `/api/exams`; доступность и состав данных зависят от Platonus.
- Типы PDF УМКД заданы фиксированными `fileTypeID` 131/133/134/138; другие наборы требуют проверки ответа Platonus.
- Формат журнала, календаря и учебных полей зависит от Platonus. Изменения парсинга проверяй на обезличенных примерах, не добавляя реальные ответы с личными данными в Git.
- Инструменты переноса базы отделены в `scripts/maintenance/`; они не участвуют в сборке или работе сайта. [Инструкция](database-maintenance.md).
