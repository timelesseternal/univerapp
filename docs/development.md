# Разработка и проверка

## Быстрый запуск и проверка

- Данные для отображения (профиль, расписание, оценки и УМКД) зеркалируются в
  localStorage с отдельным префиксом для пользователя Telegram. Повторное открытие
  показывает кэш, свежие данные запрашиваются в фоне. Сессия и пароль в Telegram
  по-прежнему хранятся только в CloudStorage.
- Чтения CloudStorage объединяются в пакетные запросы и имеют таймаут 5 секунд.
  Данные больше лимита CloudStorage в 4096 символов сохраняются локально.
- Расписание при известном studentID не ждёт обновления GPA. Одновременные ошибки
  истёкшей сессии используют один запрос повторного входа.
  При известном семестре готовые оценки и УМКД отображаются, пока расписание ещё
  загружается. Ответы предыдущего аккаунта отбрасываются после выхода.
- Фон рисуется кодом на Canvas 2D, без загрузки видео. Разрешение ограничено 240 000 пикселями, движение — 24–30 кадрами в секунду. Анимация запускается после готовности интерфейса, останавливается при скрытии приложения, prefers-reduced-motion и saveData. Тема и акцент обновляют палитру без сброса движения.
  Manrope хранится в `assets/fonts/manrope/`
  (около 42 КБ суммарно), без запросов к Google Fonts при открытии приложения.
  Поддерживаются кириллица, казахские буквы и латиница; системный шрифт служит
  запасным до загрузки Manrope. Вся типографика задаётся в `assets/css/typography.css`:
  основной текст 15 px, названия предметов 16 px, подписи 12–13 px, поля ввода
  16 px. Для времени, оценок и GPA используются цифры одинаковой ширины.
- Обновление времени и прогресса пар выполняется раз в 15 секунд и при возвращении
  в приложение. В скрытой вкладке перерисовки пропускаются.
- `assets/js/sw.js` сохраняет только публичную оболочку для открытия без сети. API, видео
  и внешние ресурсы в этот кэш не попадают.
  При повторном открытии CSS и JavaScript текущей версии показываются из кэша,
  обновляясь в фоне. HTML проверяется через сеть, чтобы обнаруживать новые версии;
  при отсутствии сети используется сохранённая страница.
- `vercel.json` разрешает service worker из `assets/js/` обслуживать приложение
  в корне сайта. Для работы этого кэша на другом хостинге нужен заголовок
  `Service-Worker-Allowed: /` в ответе на запрос файла `assets/js/sw.js`.
- Проверка: `npm ci`, затем `npm test` (Node.js). Тестовая зависимость PGlite
  проверяет SQL чата в PostgreSQL; сервер приложения обращается к Supabase через `fetch`.


## Что может потребовать доработки

- Формат ответа `/journal/{year}/{term}/{studentID}` может отличаться для других
  студентов/специальностей — если увидишь ошибку или непонятные поля на вкладке
  «Оценки», пришли реальный ответ и поправим парсинг/дизайн карточки.
- В `api/umkd-file.js` типы документов УМКД (Силлабус/Конспект лекций/Планы занятий/
  Материалы контроля → `fileTypeID` 131/133/134/138) сейчас захардкожены как
  одинаковые для любой дисциплины — если для какого-то предмета набор документов
  окажется другим, нужно подтягивать типы динамически через
  `/rest/student/umkd/<id>/ru`, а не использовать фиксированный список.
- Раздел «Экзамены» пока остался как заглушка с пустым захардкоженным массивом
  (`EXAMS_SCHEDULE` в `assets/js/app.js`) — реальный эндпоинт под расписание экзаменов
  ещё не искали.
