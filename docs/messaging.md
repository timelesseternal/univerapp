# Переписки и профили

## Личные сообщения

Уведомления в **@kstuds_bot**: имя отправителя, текст и кнопка открытия переписки.
После прочтения сообщения в видимой переписке уведомление удаляется.
Для включения нужны вторая SQL-миграция и токен бота в Vercel —
[инструкция](telegram-notifications.md). Доставка выполняется в фоне.
В профиле группа и курс читаются из полей ответа Platonus, если они присутствуют;
при отсутствии данных показывается «—». В профиле отдельные плитки УМКД, экзаменов, календаря и транскрипта;
оценки доступны через нижнюю вкладку.

Вкладка «Сообщения» использует тот же вход через Platonus. Сервер подтверждает имя и
studentID, создаёт профиль чата и отдельную сессию в HttpOnly cookie на 8 часов.
Есть поиск по имени, личные переписки, история, непрочитанные сообщения и загрузка
более старых сообщений. Пользователь появляется в поиске после первого открытия
этой вкладки. Открытая переписка обновляется каждые 2,5 секунды, список — каждые
8 секунд; в скрытом приложении опрос останавливается.
При первом подключении список приходит вместе с сессией. История последних
10 просмотренных переписок (до 200 сообщений в каждой) хранится только в памяти
до выхода из аккаунта: повторное открытие показывает её сразу и проверяет новые
сообщения в фоне. Отправляемое сообщение появляется сразу с отметкой «Отправляем…»;
при ошибке оно отмечается как неотправленное, а текст сохраняется для повтора.
Опрос истории и списка выполняется параллельно, список не запрашивается при
каждом обновлении открытой переписки.

Для запуска нужны Supabase, миграции 001–006 по порядку и три обязательные
серверные переменные из `.env.example`. Пошаговая
[инструкция подключения](chat-setup.md) описывает всё без терминала.
Без настройки базы вход закрыт: она также обслуживает общий лимит попыток.
При временном сбое чата уже загруженные учебные разделы остаются доступны. Группы, вложения и звонки пока не реализованы.

Пароли и сессии Platonus в базе чата не сохраняются. В браузер не передаётся
секретный ключ Supabase. Таблицы и функции закрыты для публичных ролей; сервер
проверяет участников каждой переписки. Сообщения хранятся в базе и доступны её
администратору: сквозного шифрования в этой версии нет.


Профиль собеседника открывается нажатием на аватар в переписке. Для GPA, ID, группы и курса требуется миграция `003_peer_profiles.sql`.
