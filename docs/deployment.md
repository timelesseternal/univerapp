# Развёртывание UniLink

## Новый проект

1. Создай Supabase-проект. Vercel-функции настроены на Frankfurt (`fra1`), поэтому выбирай базу рядом с ними.
2. Выполни [SQL-миграции](../supabase/migrations) в порядке **001 → 006**. Миграция 006 обязательна для входа: она ограничивает попытки по IP и аккаунту. [Настройка базы](chat-setup.md).
3. Импортируй репозиторий в Vercel. Framework Preset — **Other**, Root Directory — корень. Команда сборки задана в `vercel.json`: `node scripts/build-release.mjs`. Она проставляет идентификатор опубликованной версии в HTML, service worker и `version.json`. Там же явно задано `outputDirectory: "."`: сайт публикуется из корня, функции лежат в `api/`. Если появляется `STATIC_BUILD_NO_OUT_DIR` с папкой `public`, проверь, что развёртывается коммит с этой настройкой.
4. Добавь серверные переменные из [.env.example](../.env.example) для нужных окружений. Production и Preview настраиваются отдельно.
5. Опубликуй проект. После изменения переменных требуется новое развёртывание.

| Переменная | Обязательность | Назначение |
| --- | --- | --- |
| `SUPABASE_URL` | Да | База чата и лимитов входа |
| `SUPABASE_SERVICE_ROLE_KEY` | Да | Серверный доступ к базе |
| `UNILINK_SESSION_KEY` | Да | Шифрование сессий и восстановление |
| `TELEGRAM_BOT_TOKEN` | Для Telegram | Проверка Mini App и уведомления |
| `TELEGRAM_BOT_USERNAME` | Для Telegram | Ссылка открытия приложения |
| `TELEGRAM_APP_SHORT_NAME` | Для именованного Mini App | Путь после имени бота |

Ключ Supabase — серверный Secret key (`sb_secret_…`) или старый `service_role`. Публичные `anon` / `publishable` не подходят. Значения не вставляются в HTML, браузерный JavaScript или Git.

Сгенерируй `UNILINK_SESSION_KEY` локально:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Сохрани результат только в Vercel. **Не меняй этот ключ при каждом редеплое:** его смена аннулирует cookie и запомненные устройства.

## Обновление существующего приложения

1. Выполни `npm ci` и `npm run verify`.
2. Применяй только новые необходимые миграции. Не запускай 001 заново поверх последующих: он может вернуть старые определения функций.
3. Отправь изменения в подключённую к Vercel ветку либо опубликуй через свой рабочий процесс. Убедись, что развёрнут новый commit: Redeploy старого развёртывания не добавляет новые локальные файлы.
4. На телефоне открой **Профиль → Обновить приложение**. Новая публикация отмечается красной точкой и текстом «Доступна новая версия». Версия проверяется при запуске, каждом нажатии на вкладку (включая активную), возвращении в приложение и раз в минуту, пока оно видно. Проверки по нажатию выполняются сразу, без минутного ограничения; одновременные запросы объединяются. Автоматической перезагрузки нет. Кнопка обновляет публичную оболочку, не удаляя аккаунт и переписки. Если на устройстве осталась старая версия без этих проверок, один раз обнови приложение вручную после публикации.
5. Для перехода на вход с ключом устройства один раз выйди и войди с «Запомнить меня». Для этого изменения не нужны SQL или дополнительный секрет.

## Проверка после публикации

- Вход, расписание, оценки, профиль, календарь, транскрипт и PDF УМКД.
- С «Запомнить меня»: полностью закрыть PWA на iPhone и открыть снова. Отдельно проверить явный выход и смену аккаунта.
- В сообщениях: видимость шапки и поля ввода при клавиатуре; возвращение таббара вниз после её закрытия.
- При настроенном боте: привязка из Telegram и уведомление на тестовой переписке.
- Для локальной истории: первая загрузка не создаёт уведомлений; после реального изменения показателя оценки или пары открой «Профиль → Что изменилось», проверь «было/стало». Проверки идут, пока приложение открыто; это не push-уведомления при закрытом приложении.
- Для офлайн-просмотра: после публикации обнови приложение, войди с «Запомнить меня», дождись расписания и экзаменов. Полностью закрой приложение, отключи интернет и открой снова. Должны отображаться сохранённые данные и время сохранения. После явного выхода офлайн-просмотр недоступен. Кэш и история относятся к конкретному аккаунту и устройству; при очистке хранилища браузером они теряются.

503 при входе означает недоступность конфигурации защиты: проверь обязательные переменные, миграцию 006 и доступ к базе. Истечение сессии на самом Platonus восстановление устройства не обходит.

[.vercelignore](../.vercelignore) исключает SQL, документацию, тесты и инструменты обслуживания из загрузки в Vercel; из `scripts/` сохраняется только сборщик версии. Заголовки безопасности, отключение кеширования `version.json` и корневая область service worker задаются в [vercel.json](../vercel.json). Повторная публикация неизменённых файлов не вызывает уведомление о новой версии.
