# Новости версий через Telegram

Публикация в Vercel автоматически создаёт commit status. Workflow `release-announcement.yml` реагирует только на успешный статус `Vercel` коммита из `main`. Перед рассылкой скрипт сравнивает версию опубликованного приложения со своей сборкой: preview, старая и неудачная публикации не рассылаются.

## Однократная настройка

1. Выполни [009_release_announcements.sql](../supabase/migrations/009_release_announcements.sql) в Supabase SQL Editor. Она создаёт отдельный журнал доставки и не меняет личные сообщения.
2. В GitHub открой репозиторий → **Settings → Secrets and variables → Actions → New repository secret**. Добавь `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `TELEGRAM_BOT_TOKEN` с теми же значениями, которые уже используются в Vercel. Не присылай значения в чат и не добавляй их в Git. Без этих secrets workflow пропустит рассылку с предупреждением.
3. При каждом обновлении отредактируй [release-notes.json](../release-notes.json): коротко перечисли изменения для студентов. В сообщении нет сырых коммитов, ключей или технических логов.
4. Если настройка выполнена уже после деплоя, открой **Actions → Announce successful production release → последний запуск → Re-run all jobs**. Следующие успешные публикации будут запускать рассылку автоматически.

Объявление начинается с «🚀 Что нового в UniLink» и содержит кнопку открытия приложения. Получатели — Telegram-аккаунты из существующих привязок чата. Бот не может писать пользователям, которые его заблокировали или не предоставили возможность отправлять сообщения.

Журнал обеспечивает не более одной попытки рассылки версии каждому получателю при повторном запуске/редеплое. Telegram 429 повторяется с указанной задержкой. Неоднозначный сетевой сбой фиксируется как `uncertain` и автоматически не повторяется: иначе можно отправить дубль. Гарантировать строго однократную доставку при сбое между Telegram и базой невозможно. Состояние `sending` после остановки workflow также не переотправляется автоматически; его нужно разбирать отдельно. Итоги видны в GitHub Actions без токенов и идентификаторов получателей.

Эта рассылка не добавляет Web Push в установленную веб-версию и не отключает существующие уведомления о личных сообщениях в боте.
