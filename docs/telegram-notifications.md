# Уведомления в @kstuds_bot

Отправитель пишет в приложении → бот присылает получателю имя и текст → кнопка
«Открыть чат» открывает эту переписку → после отображения сообщения в открытом
приложении уведомление удаляется. Простое скачивание истории или работа скрытой
вкладки не считается прочтением.

## Подключение без терминала

1. В Supabase открой **SQL Editor → New query** и выполни весь файл
   [002_telegram_notifications.sql](../supabase/migrations/002_telegram_notifications.sql).
   Первая миграция чата уже должна быть выполнена. Повторный запуск второй допустим.
   После этого не запускай первую миграцию повторно: она возвращает прежнее правило
   прочтения; если это произошло, снова выполни вторую.
2. В Vercel → проект → **Settings → Environment Variables** добавь:

   | Переменная | Значение |
   | --- | --- |
   | `TELEGRAM_BOT_TOKEN` | Токен именно **@kstuds_bot** из BotFather |
   | `TELEGRAM_BOT_USERNAME` | `kstuds_bot` |

   Токен хранится только в Vercel; не отправляй его в сообщения и не добавляй
   в GitHub. Существующие переменные Supabase остаются нужны.
3. В BotFather для @kstuds_bot настрой **Main Mini App** на адрес приложения.
   Кнопка уведомления использует ссылку
   `https://t.me/kstuds_bot?startapp=chat_<id переписки>`.
   Если используется отдельное приложение с коротким именем, вместо Main Mini App,
   добавь `TELEGRAM_APP_SHORT_NAME` со своим коротким именем — ссылка станет
   `https://t.me/kstuds_bot/<короткое имя>?startapp=…`.
4. В GitHub Desktop нажми **Commit → Push origin**. Дождись новой сборки Vercel.
   Если код уже опубликован, после добавления переменных сделай **Redeploy**.
5. Оба пользователя должны нажать **Start** у @kstuds_bot, открыть приложение
   **из этого бота** и войти через Platonus. Связь аккаунтов создаётся в фоне.
   В обычном браузере Telegram ID не угадывается и не привязывается.

## Проверка

1. Второй пользователь закрывает приложение. Первый отправляет ему сообщение.
2. У второго появляется имя отправителя, текст и кнопка «Открыть чат».
3. Нажатие открывает нужную переписку. После отображения сообщения уведомление
   исчезает из чата бота, а само сообщение остаётся в истории приложения.
4. Простой просмотр уведомления в Telegram его не удаляет: Telegram не передаёт
   боту событие прочтения. Нужно открыть переписку в приложении.

## Как устроено

- Сервер проверяет подпись `Telegram.WebApp.initData` токеном бота. Переданный
  браузером Telegram ID не используется. Нужны подтверждённые Platonus и Telegram.
- Один Telegram-аккаунт связан с текущим выбранным профилем Platonus. При входе
  другим аккаунтом привязка переключается. Старая очередь больше не доставляется
  на этот Telegram-аккаунт.
- Очередь создаётся вместе с сообщением в одной транзакции; повтор отправки не
  создаёт новую запись. Фоновые задачи Vercel доставляют уведомления после ответа
  браузеру. Повторы защищены временной блокировкой записи очереди.
- При временной ошибке отправка повторяется во время следующих отправок или
  обновлений списка чатов отправителя (до пяти попыток). Удаление повторяется
  при следующих открытиях/обновлениях переписки получателя. Это не отдельный
  непрерывный процесс: если оба приложения закрыты после сбоя сети, повтор
  произойдёт при следующей активности.
- В редком случае Telegram принял отправку, но ответ потерялся, повтор может
  создать второй экземпляр уведомления: Bot API не предоставляет ключа
  идемпотентности отправки. Обычный повтор сообщения в приложении не дублируется.
- Telegram разрешает удалять уведомления только в течение **48 часов после
  отправки**. Более старые остаются в чате бота. Блокировка бота или отсутствие
  разрешения писать пользователю не ломает переписку в приложении.

Официальная справка: [проверка данных Mini App](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app),
[удаление сообщений](https://core.telegram.org/bots/api#deletemessage).
