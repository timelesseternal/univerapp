# Защита входа UniLink

## Перед публикацией

1. Выполните [006_login_rate_limit.sql](../supabase/migrations/006_login_rate_limit.sql) в SQL Editor Supabase. Миграция допускает повторный запуск.
2. Создайте серверный секрет: `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`. Сохраните результат только в переменной окружения Vercel `UNILINK_SESSION_KEY` для нужных окружений. Не добавляйте ключ в Git или файлы сайта.
3. Проверьте серверные `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`, затем опубликуйте новую версию. Без ключа или работающей миграции вход закрывается с ошибкой 503.
4. Обновите приложение. Старая авторизация через заголовок больше не поддерживается. Пользователям потребуется войти заново.

## Что изменилось

- Пароль передаётся серверу и далее Platonus по HTTPS только для входа. UniLink не записывает его в хранилища или журналы. Старые ключи `platonus_session`, `platonus_login`, `platonus_password` удаляются из браузера и Telegram CloudStorage при запуске.
- Сервер шифрует данные сессии Platonus через AES-256-GCM со случайным IV. Браузер получает cookie `unilink_session`: `HttpOnly`, `SameSite=Strict`, `Secure` на HTTPS. Сессия не возвращается в JSON и не принимается через URL или `x-session`.
- При включённом «Запомнить меня» cookie и зашифрованная сессия UniLink действуют до 30 дней с момента входа. Без этой опции используется cookie браузерной сессии с ограничением 8 часов. Platonus может завершить свой вход раньше. Автоматического входа сохранённым паролем нет. Для перехода со старого восьмичасового срока нужно один раз войти заново после публикации обновления.
- Постоянная cookie содержит `Max-Age` и `Expires`. При запуске форма входа скрыта до проверки cookie. Только ответ 401 означает отсутствие действующей сессии; ошибки сети, тайм-ауты и ошибки сервера оставляют возможность повторить проверку, не удаляя вход и кэш аккаунта.
- Выход удаляет cookie и кэш аккаунта, ждёт завершения старого запроса входа перед очисткой. Он не отзывает сессию на сервере Platonus. Скопированная cookie может действовать до истечения срока; смена `UNILINK_SESSION_KEY` аннулирует все такие cookie UniLink.
- Общие лимиты Supabase: 8 попыток для аккаунта и 30 для IP за 10 минут. Считаются все попытки, включая успешные. IP и логины заменяются HMAC; пароль в базу не попадает. Неактуальные записи очищаются при новых попытках входа.
- Проверка Origin/Sec-Fetch-Site блокирует запросы с чужих сайтов. Заголовки Vercel ограничивают исполняемые скрипты, встраивание, доступ к камере/микрофону и передачу адреса страницы. HTML-обработчики заменены списком разрешённых действий без `eval`. Обработка PDF также запускается без `eval`.
- Скачивание PDF использует уже полученный файл и системное меню «Поделиться» или Blob. Внешнему загрузчику Telegram ссылка с сессией больше не передаётся.

## Границы защиты

Это защита входа и браузерного приложения, а не сквозное шифрование чата. Сообщения остаются в Supabase с существующими проверками участников. Данные для отображения профиля и учёбы могут оставаться в кэше устройства до выхода; они не зашифрованы этим изменением. Cookie не синхронизируется через Telegram между устройствами.

Ключ, сервисный ключ Supabase и доступ к Vercel должны оставаться закрытыми. Ограничение IP предполагает доверенный прокси Vercel, который задаёт `x-forwarded-for`; при самостоятельном размещении потребуется настроить доверенный источник IP. Проверки интерфейса и API не заменяют проверку на реальном iPhone и в Telegram после публикации.
