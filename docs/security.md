# Вход, сессии и хранение данных

## Настройка

Вход требует `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `UNILINK_SESSION_KEY` и [миграцию 006](../supabase/migrations/006_login_rate_limit.sql). Ключ сессий — 32 случайных байта в виде 64 hex-символов. Он хранится только на сервере и остаётся одинаковым между развёртываниями. [Порядок настройки](deployment.md).

## Пароль и cookie

Пароль передаётся серверу и Platonus по HTTPS только при явном входе. Он не записывается в базу, файлы, журналы, браузерное хранилище или Telegram CloudStorage. Старые ключи `platonus_session`, `platonus_login`, `platonus_password` удаляются при запуске.

Сервер шифрует сессию Platonus через AES-256-GCM со случайным IV. Основной доступ к API использует `unilink_session`: `HttpOnly`, `SameSite=Strict`, `Secure` на HTTPS, путь `/api`. API не принимает сессию в URL или `x-session` и не возвращает читаемые токены Platonus интерфейсу.

- С «Запомнить меня» срок UniLink — до **30 дней от входа**; cookie содержит `Max-Age` и `Expires`.
- Без этой опции — браузерная cookie до **8 часов**, без записи для восстановления устройства.
- Platonus может завершить свою сессию раньше. Пароль для автоматического входа в университетскую систему не сохраняется.

## Восстановление после закрытия PWA

Cookie остаётся основным способом доступа. У запомненного входа есть независимый от неё путь восстановления:

1. При явном входе браузер создаёт пару ECDSA P-256. Приватный `CryptoKey` неэкспортируемый; сервер получает только публичный ключ.
2. При успешном входе сервер выдаёт пакет `deviceSession`: AES-256-GCM, отдельное назначение шифрования, привязка к хосту, сессия Platonus и публичный ключ внутри. Этот пакет не принимается как обычная API-cookie.
3. Приватный ключ и зашифрованный пакет сохраняются в IndexedDB этого браузера и сайта. В localStorage и Telegram CloudStorage их нет. Запись завершается до открытия приложения после входа; ошибка сохранения показана пользователю.
4. Если `/api/session` отвечает 401, браузер запрашивает короткий challenge. Он привязан к конкретному пакету и хосту, проверяется через HMAC и действует 60 секунд.
5. Устройство подписывает challenge. Только после проверки подписи сервер восстанавливает HttpOnly cookie. Копия одного пакета без приватного ключа не подходит.

Восстановление сохраняет **первоначальную дату истечения**: повторные открытия не продлевают 30 дней. Запросы и ответы восстановления не журналируются. Доказательство может быть повторено в пределах своего короткого срока; оно передаётся только по HTTPS. Неэкспортируемый ключ — ограничение Web Crypto, а не гарантия аппаратного хранения или защита от выполняющегося в этом же origin вредоносного кода. Справка: [CryptoKey](https://developer.mozilla.org/en-US/docs/Web/API/CryptoKey/extractable), [хранение ключей Web Crypto](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto).

После обновления с cookie-only версии нужно один раз войти заново с «Запомнить меня». Новых переменных или SQL нет. Если IndexedDB или Web Crypto недоступны, можно войти без запоминания. Полная очистка данных сайта, другой браузер или домен, истечение Platonus либо смена серверного ключа потребуют нового входа.

Ошибки сети, тайм-ауты и 5xx предлагают повторить проверку, не объявляя пользователя вышедшим. Подтверждённое отсутствие действующего входа открывает форму пароля. Ответы старого аккаунта отбрасываются по поколению авторизации.

## Выход и отзыв

Явный выход удаляет cookie, ключ устройства, пакет восстановления и кэш аккаунта. Он ждёт незавершённый вход или восстановление, чтобы запоздалый ответ не вернул cookie. Запись устройства и её удаление выполняются последовательно.

Сессия чата отзывается в Supabase. Основная сессия не отзывается на сервере Platonus; централизованного списка отозванных устройств нет. Скопированная cookie или полная пригодная для подписи копия профиля браузера могут действовать до истечения срока. Смена `UNILINK_SESSION_KEY` аннулирует все сессии UniLink и пакеты восстановления.

## Остальная защита

- Общие лимиты Supabase: 8 попыток для аккаунта и 30 для IP за 10 минут, включая успешные. IP и логины заменяются HMAC; пароль в базу не попадает.
- Origin и Sec-Fetch-Site блокируют запросы с чужих сайтов. Восстановление проходит те же проверки.
- CSP ограничивает скрипты своим origin, SDK Telegram и закреплённой версией PDF.js. HTML-действия используют разрешённые имена без `eval`; PDF открывается с `isEvalSupported: false`.
- HSTS, `nosniff`, запрет камеры/микрофона/платежей, ограничения встраивания и `no-referrer` настроены в Vercel.
- PDF скачивается через полученный Blob, без сессий в ссылках внешним загрузчикам.
- Supabase service key остаётся на сервере. Сервер проверяет участников переписки; публичные роли не читают таблицы напрямую.

Это не сквозное шифрование чата. Сообщения хранятся в Supabase и доступны администратору базы. Учебные данные могут оставаться в локальном кэше до выхода и не зашифрованы этим механизмом. Service worker кэширует только публичную оболочку, не API или историю чата.

Тесты покрывают утрату cookie, перезапуск скрипта, чужой ключ, подмену пакета, короткий challenge, исходный срок, ошибки сети и гонки выхода. Настоящее завершение PWA на iPhone проверяется отдельно после публикации.
