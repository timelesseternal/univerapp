# Вход, сессии и хранение данных

## Настройка

Вход требует `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `UNILINK_SESSION_KEY` и [миграцию 006](../supabase/migrations/006_login_rate_limit.sql). Ключ сессий — 32 случайных байта в виде 64 hex-символов. Он хранится только на сервере и остаётся одинаковым между развёртываниями. [Порядок настройки](deployment.md).

## Пароль и cookie

Пароль передаётся серверу и Platonus по HTTPS. Без «Запомнить меня» он используется только при явном входе. С этой опцией логин и пароль включаются в зашифрованный сервером пакет устройства, чтобы повторно войти при завершении сессии Platonus. Открытого пароля нет в браузерном хранилище, API-cookie, базе, файлах, журналах или Telegram CloudStorage. Старые ключи `platonus_session`, `platonus_login`, `platonus_password` удаляются при запуске.

Сервер шифрует сессию Platonus через AES-256-GCM со случайным IV. Основной доступ к API использует `unilink_session`: `HttpOnly`, `SameSite=Strict`, `Secure` на HTTPS, путь `/api`. API не принимает сессию в URL или `x-session` и не возвращает читаемые токены Platonus интерфейсу.

- С «Запомнить меня» срок UniLink — до **30 дней от входа**; cookie содержит `Max-Age` и `Expires`.
- Без этой опции — браузерная cookie до **8 часов**, без записи для восстановления устройства.
- Если Platonus завершает сессию раньше, устройство подтверждает владение ключом, после чего сервер повторно входит через Platonus. Вызов проходит общий лимит попыток. Повторный 401 отдельного маршрута после успешного обновления не вызывает полный выход.

## Восстановление после закрытия PWA

Cookie остаётся основным способом доступа. У запомненного входа есть независимый от неё путь восстановления:

1. При явном входе создаётся пара ECDSA P-256. Сервер получает только публичный ключ. Браузерный вариант хранит неэкспортируемый приватный `CryptoKey`.
2. При успешном запомненном входе сервер выдаёт пакет `deviceSession`: AES-256-GCM, отдельное назначение шифрования, привязка к хосту, сессия Platonus, учётные данные для обновления и публичный ключ внутри. Расшифровать пакет может только сервер с `UNILINK_SESSION_KEY`. Этот пакет не принимается как обычная API-cookie.
3. В обычном браузере приватный ключ и пакет сохраняются в IndexedDB этого сайта. В Telegram с Bot API 9.0+ основное хранилище — SecureStorage (Keychain на iOS, Keystore на Android). Для него приватный ключ временно экспортируется как JWK и вместе с зашифрованным пакетом записывается только в защищённое хранилище Telegram; для подписи и резервной копии IndexedDB он импортируется неэкспортируемым. В localStorage и Telegram CloudStorage этих данных нет. Браузерная копия разделена по Telegram-пользователю, нативная — по боту, пользователю и домену приложения.
4. Если `/api/session` отвечает 401, браузер запрашивает короткий challenge. Он привязан к конкретному пакету и хосту, проверяется через HMAC и действует 60 секунд.
5. Устройство подписывает challenge. Только после проверки подписи сервер восстанавливает HttpOnly cookie. Если университетская сессия отклонена, запрос с `refresh: true` повторно входит в Platonus и возвращает обновлённый зашифрованный пакет с прежней датой истечения. Устройство сохраняет его с тем же ключом. Копия одного пакета без приватного ключа не подходит.

Восстановление сохраняет **первоначальную дату истечения**: повторные открытия не продлевают 30 дней. Запросы и ответы восстановления не журналируются. Доказательство может быть повторено в пределах своего короткого срока; оно передаётся только по HTTPS. Неэкспортируемый ключ — ограничение Web Crypto, а не гарантия аппаратного хранения или защита от выполняющегося в этом же origin вредоносного кода. Справка: [CryptoKey](https://developer.mozilla.org/en-US/docs/Web/API/CryptoKey/extractable), [хранение ключей Web Crypto](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto).

После обновления пакета сессии без учётных данных нужно один раз войти заново с «Запомнить меня». Новых переменных или SQL нет. Сбой сохранения или недоступность IndexedDB / Web Crypto не блокирует успешный вход: остаётся серверная cookie, но при её потере повторный вход может понадобиться. Автоматический вызов SecureStorage.restoreItem с запросом дополнительных разрешений не используется. Справка: [SecureStorage Telegram](https://core.telegram.org/bots/webapps#securestorage). Полная очистка данных сайта, другой браузер или домен, смена пароля, истечение 30 дней либо смена серверного ключа потребуют нового входа. Ошибка автоматического восстановления не создаёт отметку явного выхода и не удаляет сохранённый пакет; неверный пароль или истёкший пакет удаляются отдельно.

Ошибки сети, тайм-ауты и 5xx предлагают повторить проверку, не объявляя пользователя вышедшим. Подтверждённое отсутствие действующего входа открывает форму пароля. Ответы старого аккаунта отбрасываются по поколению авторизации.

## Выход и отзыв

Явный выход удаляет cookie, ключ устройства, пакет восстановления и кэш аккаунта. Он ждёт незавершённый вход или восстановление, чтобы запоздалый ответ не вернул cookie. Запись устройства и её удаление выполняются последовательно. До сетевых запросов сохраняется локальная отметка выхода: если DELETE не прошёл без сети, оставшаяся cookie не восстанавливает вход автоматически. Отметка снимается только после успешного явного входа. Если браузер запрещает локальное хранилище или пользователь очищает его, сохранить эту отметку между запусками невозможно.

Сессия чата отзывается в Supabase. Основная сессия не отзывается на сервере Platonus; централизованного списка отозванных устройств нет. Скопированная cookie или полная пригодная для подписи копия профиля браузера могут действовать до истечения срока. Смена `UNILINK_SESSION_KEY` аннулирует все сессии UniLink и пакеты восстановления.

## Остальная защита

- Общие лимиты Supabase: 8 попыток для аккаунта и 30 для IP за 10 минут, включая успешные. IP и логины заменяются HMAC; пароль в базу не попадает.
- Origin и Sec-Fetch-Site блокируют запросы с чужих сайтов. Восстановление проходит те же проверки.
- CSP ограничивает скрипты своим origin, SDK Telegram и закреплённой версией PDF.js. HTML-действия используют разрешённые имена без `eval`; PDF открывается с `isEvalSupported: false`.
- HSTS, `nosniff`, запрет камеры/микрофона/платежей, ограничения встраивания и `no-referrer` настроены в Vercel.
- PDF скачивается через полученный Blob, без сессий в ссылках внешним загрузчикам.
- Supabase service key остаётся на сервере. Сервер проверяет участников переписки; публичные роли не читают таблицы напрямую.

Это не сквозное шифрование чата. Сообщения хранятся в Supabase и доступны администратору базы. Учебные данные могут оставаться в локальном кэше до выхода и не зашифрованы этим механизмом. Service worker кэширует только публичную оболочку, не API или историю чата.

Тесты покрывают утрату cookie, перезапуск скрипта, чужой ключ, подмену пакета, короткий challenge, исходный срок, ошибки сети и гонки выхода. Настоящее завершение PWA на iPhone проверяется отдельно после публикации.
