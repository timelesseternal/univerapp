# Обслуживание и перенос базы

Обычное обновление UniLink не требует переноса базы. Для изменений схемы используй [миграции](../supabase/migrations) в порядке их номеров. Смена региона существующего проекта — отдельная операция с резервной копией и проверкой данных.

## Инструмент подготовки переноса

[prepare-supabase-transfer.mjs](../scripts/maintenance/prepare-supabase-transfer.mjs) — специализированный инструмент для формата снимка, использованного при переносе Sydney → Frankfurt. Он не получает данные по сети и не переносит произвольный Supabase-проект автоматически.

```sh
node scripts/maintenance/prepare-supabase-transfer.mjs /absolute/path/to/private-backup
```

В переданном каталоге ожидается `sydney-backup.json` с таблицами, колонками, индексами, ограничениями, функциями, ACL, триггерами и данными. Результат и отчёты создаются там же. Скрипт проверяет ожидаемый набор восьми таблиц, отсутствие Auth-пользователей и Storage-объектов, права RPC; затем проверяет подготовленный SQL в PGlite. Изменённая схема или другой формат требуют отдельного пересмотра инструмента.

Сгенерированный SQL отказывается работать с уже занятой целевой public-схемой. Это предохранитель, а не универсальная проверка всего проекта. Auth, Storage, внешние интеграции и настройки Supabase не входят в этот перенос.

## Порядок работ

1. Сделай проверяемую резервную копию и сохрани её **вне репозитория**. Выгрузка включает личные сообщения и данные пользователей.
2. Подготовь пустой целевой проект и отдельно проверь регион и тариф.
3. Сверь схемы и данные, выполни восстановление только в целевом проекте. На время финального снимка останови записи либо отдельно перенеси изменения, сделанные после снимка.
4. Сравни таблицы, числа и содержимое записей, ограничения, индексы, функции, права и триггеры. Один успешный запуск SQL ещё не подтверждает полноценный перенос.
5. Замени серверные `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`, опубликуй приложение, проверь вход, чат и уведомления.
6. Сохрани старую базу до подтверждения переноса; её удаление выполняется отдельно.

`.gitignore` и `.vercelignore` исключают стандартный каталог приватного переноса и выгрузки. Это не заменяет выбор безопасного каталога и проверку перед коммитом. Не публикуй восстановительные SQL с данными, ключи или полные ответы API.
