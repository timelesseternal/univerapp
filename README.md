# Univer KSTU — вход через Platonus

## Что внутри

```text
univerapp/
├── index.html             # Разметка Mini App
├── README.md              # Документация
├── package.json           # Команды проекта
├── vercel.json            # Настройки размещения
├── assets/
│   ├── css/
│   │   ├── app.css         # Оформление и расположение элементов
│   │   ├── chat.css        # Личные переписки
│   │   └── typography.css # Шрифты, размеры текста и межстрочные интервалы
│   ├── fonts/
│   │   └── manrope/       # Локальные WOFF2-файлы и лицензия OFL
│   ├── js/
│   │   ├── appearance.js  # Применение темы до первого отображения
│   │   ├── app.js         # Логика приложения
│   │   ├── chat.js        # Поиск пользователей и сообщения
│   │   ├── background.js  # Управление видеофоном
│   │   └── sw.js          # Кэш публичной оболочки
│   └── media/
│       └── background.mp4
├── api/                   # Серверные обработчики Vercel
│   └── _lib/              # Общие серверные функции
├── supabase/migrations/   # SQL для базы чата
├── docs/                  # Инструкции по подключению
└── tests/                 # Автоматические проверки
```

- `index.html` — разметка экранов и подключение ресурсов. Стили и JavaScript
  вынесены в `assets/`, где браузер может кэшировать их отдельно от страницы.
- `assets/js/app.js` — вход, расписание с переключением недель, оценки,
  УМКД (с открытием PDF прямо внутри приложения), заготовка под экзамены.
- `api/login.js` — логинится в Platonus от имени студента, отдаёт временный `session`
  (без пароля).
- `api/gpa.js` — GPA + studentID/имя студента (используется сразу после входа).
- `api/schedule.js` — расписание из Platonus. Без явных параметров сам разбирается,
  какая неделя сейчас настоящая текущая (см. ниже про особенности недель);
  с явными `year`/`term`/`week` отдаёт расписание конкретной недели — так работает
  листание стрелками в приложении.
- `api/grades.js` — оценки/успеваемость по предметам (журнал): каждый предмет —
  проценты (`centerMark`, `color`) плюс список показателей (`exams`: Ср.тек. 1/2,
  РК 1/2, Рейтинг, Экз./Курс.р.).
- `api/umkd.js` — список дисциплин УМКД на семестр (название, преподаватель,
  готов ли файл — `umkdFileGenerated`/`fileId`).
- `api/umkd-file.js` — отдаёт сам PDF конкретного документа УМКД (Силлабус/Конспект
  лекций/Планы занятий/Материалы контроля), проксируя `downloadPdfUmkd` у Platonus.
  Открывается через `<iframe>` прямо в приложении, поэтому сессия здесь может
  прийти и через query-параметр `?session=`, а не только через заголовок
  (у iframe нет возможности выставить кастomный заголовок).
- `api/_lib/platonus.js` — общие хелперы (сборка заголовков, кодирование/декодирование
  сессии).

## Как задеплоить (Vercel)

1. Зайди на https://vercel.com, войди через GitHub.
2. Создай новый репозиторий на GitHub, залей туда содержимое этой папки целиком
   (включая `index.html`, `assets/`, `api/`, `package.json` и `vercel.json`).
3. На vercel.com → **Add New → Project** → выбери этот репозиторий.
4. Framework Preset — оставь **Other**. Учебные разделы работают без переменных
   окружения. Для чата подключи Supabase по [инструкции](docs/chat-setup.md).
5. Нажми **Deploy**. Через минуту получишь адрес вида
   `https://твой-проект.vercel.app`.
6. Проверь: открой этот адрес в браузере, попробуй войти своим логином/паролем от Platonus —
   должно появиться расписание, GPA, оценки и список УМКД.
7. В BotFather (Telegram) укажи этот URL как адрес Mini App вместо старого.

## Быстрый запуск и проверка

- Данные для отображения (профиль, расписание, оценки и УМКД) зеркалируются в
  localStorage с отдельным префиксом для пользователя Telegram. Повторное открытие
  показывает кэш, свежие данные запрашиваются в фоне. Сессия и пароль в Telegram
  по-прежнему хранятся только в CloudStorage.
- Чтения CloudStorage объединяются в пакетные запросы и имеют таймаут 5 секунд.
  Данные больше лимита CloudStorage в 4096 символов сохраняются локально.
- Расписание при известном studentID не ждёт обновления GPA. Одновременные ошибки
  истёкшей сессии используют один запрос повторного входа.
  При известном семестре готовые оценки и УМКД отображаются, пока расписание ещё
  загружается. Ответы предыдущего аккаунта отбрасываются после выхода.
- Фоновое видео запускается после готовности интерфейса; при экономии трафика или
  reduced motion остаётся CSS-фон. Конец и начало ролика соединяются переходом
  длительностью 1,2 секунды: второй видеослой воспроизводится только во время
  перехода, затем предыдущий слой ставится на паузу и готовится к следующему циклу.
  При скрытии приложения оба слоя останавливаются.
  Manrope хранится в `assets/fonts/manrope/`
  (около 42 КБ суммарно), без запросов к Google Fonts при открытии приложения.
  Поддерживаются кириллица, казахские буквы и латиница; системный шрифт служит
  запасным до загрузки Manrope. Вся типографика задаётся в `assets/css/typography.css`:
  основной текст 15 px, названия предметов 16 px, подписи 12–13 px, поля ввода
  16 px. Для времени, оценок и GPA используются цифры одинаковой ширины.
- Обновление времени и прогресса пар выполняется раз в 15 секунд и при возвращении
  в приложение. В скрытой вкладке перерисовки пропускаются.
- `assets/js/sw.js` сохраняет только публичную оболочку для открытия без сети. API, видео
  и внешние ресурсы в этот кэш не попадают.
  При повторном открытии CSS и JavaScript текущей версии показываются из кэша,
  обновляясь в фоне. HTML проверяется через сеть, чтобы обнаруживать новые версии;
  при отсутствии сети используется сохранённая страница.
- `vercel.json` разрешает service worker из `assets/js/` обслуживать приложение
  в корне сайта. Для работы этого кэша на другом хостинге нужен заголовок
  `Service-Worker-Allowed: /` в ответе на запрос файла `assets/js/sw.js`.
- Проверка: `npm ci`, затем `npm test` (Node.js). Тестовая зависимость PGlite
  проверяет SQL чата в PostgreSQL; сервер приложения обращается к Supabase через `fetch`.

## Личные сообщения

Уведомления в **@kstuds_bot**: имя отправителя, текст и кнопка открытия переписки.
После прочтения сообщения в видимой переписке уведомление удаляется.
Для включения нужны вторая SQL-миграция и токен бота в Vercel —
[инструкция](docs/telegram-notifications.md). Доставка выполняется в фоне.
В профиле группа и курс читаются из полей ответа Platonus, если они присутствуют;
при отсутствии данных показывается «—». Меню профиля содержит УМКД и экзамены;
оценки доступны через нижнюю вкладку.

Вкладка «Чаты» использует тот же вход через Platonus. Сервер подтверждает имя и
studentID, создаёт профиль чата и отдельную сессию в HttpOnly cookie на 8 часов.
Есть поиск по имени, личные переписки, история, непрочитанные сообщения и загрузка
более старых сообщений. Пользователь появляется в поиске после первого открытия
этой вкладки. Открытая переписка обновляется каждые 2,5 секунды, список — каждые
8 секунд; в скрытом приложении опрос останавливается.
При первом подключении список приходит вместе с сессией. История последних
10 просмотренных переписок (до 200 сообщений в каждой) хранится только в памяти
до выхода из аккаунта: повторное открытие показывает её сразу и проверяет новые
сообщения в фоне. Отправляемое сообщение появляется сразу с отметкой «Отправляем…»;
при ошибке оно отмечается как неотправленное, а текст сохраняется для повтора.
Опрос истории и списка выполняется параллельно, список не запрашивается при
каждом обновлении открытой переписки.

Для запуска нужен новый проект Supabase, SQL из `supabase/migrations/001_chat.sql`
и две серверные переменные Vercel из `.env.example`. Пошаговая
[инструкция подключения](docs/chat-setup.md) описывает всё без терминала.
Без настройки базы остальные разделы продолжают работать, а чат показывает
сообщение о подключении. Группы, вложения и звонки пока не реализованы.

Пароли и сессии Platonus в базе чата не сохраняются. В браузер не передаётся
секретный ключ Supabase. Таблицы и функции закрыты для публичных ролей; сервер
проверяет участников каждой переписки. Сообщения хранятся в базе и доступны её
администратору: сквозного шифрования в этой версии нет.

## Важно про безопасность

- Пароль студента отправляется один раз, напрямую в Platonus, по HTTPS.
  Он нигде не логируется и не сохраняется на сервере — используется и тут же забывается
  (сам пароль всё же сохраняется на устройстве студента через Telegram CloudStorage,
  чтобы не вводить его при каждом открытии — см. ниже).
- Вместо пароля клиенту возвращается `session` — обёртка над `sid`/`token`/`cookie`,
  которые Platonus сам выдаёт после входа. Это то же самое, что обычная веб-сессия сайта.
- `session` (и логин/пароль для тихого повторного входа) хранятся через
  **Telegram CloudStorage** — она переживает очистку кэша WebView и синхронизируется
  с аккаунтом Telegram, в отличие от `localStorage`. Вне Telegram (локальная разработка
  в обычном браузере) используется `localStorage` как запасной вариант.
  При компрометации устройства это даёт доступ к аккаунту, пока сессия жива на стороне
  Platonus. Кнопка «Выйти» в приложении стирает всё локально — сама сессия на Platonus
  продолжит жить, пока не истечёт сама или пока студент не сменит пароль / не завершит
  сессии в настройках Platonus.
- Если бэкенд отдаёт `401 session_expired` — фронт сам пробует тихо перелогиниться
  сохранённым логином/паролем, а если не выходит — разлогинивает и просит войти заново.

## Особенности номера недели (важно, если будешь трогать `api/schedule.js`)

Platonus странно ведёт себя с недельной нумерацией без явных параметров:
- Если не передавать `year`/`term`/`week` вообще, поле `selectedWeek` в ответе иногда
  возвращает "заглушку" (например `1`), которая не совпадает с реальной текущей неделей.
  Надёжнее в этом случае поля `defaultSelectedWeek`/`activeWeekNumber` — они не зависят
  от того, что было запрошено, и всегда указывают на настоящую текущую учебную неделю.
- Если же `year`/`term`/`week` переданы явно (навигация стрелками в приложении),
  `selectedWeek` в ответе корректно отражает именно то, что было запрошено — тогда
  доверяем именно ему.
- Приложение сохраняет это как флаг `hadExplicitOverride` при разборе ответа
  (`buildScheduleEntryFromPlatonus` в `assets/js/app.js`) — если будешь менять логику
  выбора недели, важно сохранить это разделение.
- Недели у Platonus 1-based (первая неделя семестра — «1», не «0») и их максимум
  обычно 15 за семестр — это захардкожено в `MAX_TERM_WEEKS`.
- Расписание каждой открытой недели кэшируется отдельно (в памяти и в Telegram
  CloudStorage, ключи вида `platonus_week_<year>-<term>-<week>`), поэтому повторное
  открытие уже просмотренной недели показывается мгновенно, а свежие данные
  подтягиваются в фоне.

## Что может потребовать доработки

- Формат ответа `/journal/{year}/{term}/{studentID}` может отличаться для других
  студентов/специальностей — если увидишь ошибку или непонятные поля на вкладке
  «Оценки», пришли реальный ответ и поправим парсинг/дизайн карточки.
- В `api/umkd-file.js` типы документов УМКД (Силлабус/Конспект лекций/Планы занятий/
  Материалы контроля → `fileTypeID` 131/133/134/138) сейчас захардкожены как
  одинаковые для любой дисциплины — если для какого-то предмета набор документов
  окажется другим, нужно подтягивать типы динамически через
  `/rest/student/umkd/<id>/ru`, а не использовать фиксированный список.
- Раздел «Экзамены» пока остался как заглушка с пустым захардкоженным массивом
  (`EXAMS_SCHEDULE` в `assets/js/app.js`) — реальный эндпоинт под расписание экзаменов
  ещё не искали.
